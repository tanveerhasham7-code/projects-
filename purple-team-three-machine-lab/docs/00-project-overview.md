# 00 — Project Overview and Learning Foundations

## 1. What is a Purple Team?

A red team tests security by simulating attacker behavior under authorization. A blue team monitors, detects, investigates, and responds. A purple team connects both sides so that every simulation teaches the defenders something measurable.

In this lab, Kali is used for carefully limited security tests. Windows and Ubuntu generate endpoint and service telemetry. Wazuh is used to centralize and review available events.

## 2. The three systems

### Windows Endpoint
A Windows virtual machine representing an employee workstation. It should generate Security log events and, when configured, Sysmon process and network telemetry. The Wazuh agent forwards supported events to the manager.

### Ubuntu Server
An Ubuntu virtual machine representing a Linux server. It can host a simple web service and SSH service for lab-only tests. Authentication and web access logs provide evidence of activity.

### Kali Linux
A security-testing workstation. Use it only to test the Windows and Ubuntu VMs on the isolated lab subnet. Kali is not a target outside this lab.

### Wazuh management
Wazuh Manager, Indexer, and Dashboard collect, index, and display security data. They may be on an existing management VM. The manager is not automatically one of the three endpoints.

## 3. Important terms

- Asset: a system or resource that needs protection.
- Attack surface: places where a system can be interacted with.
- Telemetry: data generated by systems, such as process, authentication, and network events.
- Log: a recorded event or message.
- SIEM: a platform that collects and helps analyze security events.
- Agent: endpoint software that sends selected data to a manager.
- Indicator: an observable clue, such as an unusual process or repeated login failure.
- Detection: logic that identifies a behavior worth reviewing.
- Alert: a notification produced by a rule or analytic.
- Investigation: a structured process to determine what happened.
- False positive: an alert that matched benign activity.
- False negative: a test behavior occurred but the detection did not alert.
- Purple-team validation: checking whether a known safe simulation produced expected telemetry and detection.

## 4. End-to-end workflow

1. Define a question and hypothesis.
2. Confirm the lab is isolated and healthy.
3. Record the baseline.
4. Perform one safe test from Kali.
5. Record the exact time and target.
6. Find the resulting event on the target.
7. Confirm whether Wazuh received it.
8. Evaluate the alert or detection.
9. Investigate context and benign explanations.
10. Record outcome, evidence, gaps, and improvement.

## 5. What success means

Success does not mean "Kali found something." Success means the learner can explain what was tested, why it was safe, what event was expected, what actually happened, whether the SIEM received it, whether a detection fired, and what limitations remain.
